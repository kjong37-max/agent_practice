# Commit Convention

## 커밋 메시지 구조

```
<type>(<scope>): <subject>

<body>

<footer>
```

---

## Type (타입)

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 (코드 변경 없음) |
| `style` | 코드 포맷 변경 (세미콜론 누락 등, 로직 변경 없음) |
| `refactor` | 코드 리팩토링 (기능 추가 및 버그 수정 없음) |
| `test` | 테스트 추가 또는 수정 |
| `chore` | 빌드 설정, 패키지 관리 등 기타 변경 |

---

## Subject (제목)

- 50자 이내로 작성
- 마침표 없이 끝내기
- 명령형으로 작성 (예: "변경한다", "추가한다")
- 한글 또는 영어 사용 (팀 내 통일)

---

## Body (본문) — 선택사항

- 72자마다 줄바꿈
- **무엇을** 변경했는지, **왜** 변경했는지 설명
- 어떻게 변경했는지는 생략 가능 (코드에서 확인 가능)

---

## Footer (푸터) — 선택사항

- 이슈 참조: `Closes #123`, `Refs #456`
- 브레이킹 체인지: `BREAKING CHANGE: <설명>`

---

## 예시

```
feat(auth): 로그인 기능 추가

사용자 이메일과 비밀번호를 통한 로그인 기능을 구현했습니다.
JWT 토큰을 발급하여 세션을 관리합니다.

Closes #42
```

```
fix(api): 회원가입 시 중복 이메일 오류 처리
```

```
docs: README에 설치 방법 추가
```
